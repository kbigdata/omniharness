# 완전 자동 루프 — 설계 검토

omniharness 플러그인 위에 **완전 자동(무인) 루프**를 얹을 수 있는지에 대한 설계 검토.
구현 전 단계의 분석 문서이며, [하네스 갭분석](하네스-엔지니어링-갭분석.md)의 Phase 4(무인 자율 운영)와 §2-6 방향성에 정합한다.

## 0. 한 줄 결론

> 가능하다. 갭분석이 "하네스 본체"로 규정한 **강제 계층·신선검증·인계 아티팩트**는 이미 플러그인이 구현했고, 빠진 건 **세션 밖 루프 드라이버 하나**다. 드라이버의 두 핵심 책임은 (a) 인계를 프롬프트 본문에 직접 주입, (b) 검증을 모델 밖에서 독립 실행이다.

> **구현 상태(2026-07-02)**: 드라이버 `scripts/autoloop.py` — Python+subprocess 단일 코어(SDK 없음, 크로스플랫폼) + 얇은 런처(`.sh`/`.ps1`/`.bat`). **오프라인 제어흐름 검증됨**(`tests/run.sh` 4단언). **실모델 e2e 3건 통과**: (성공) `greet` 기능을 무인으로 구현→evaluator 독립검증(PASS)→기록→커밋 완주(exit 0); (한계) 회귀 항상 실패 시 보류·exit 1·`passes` false 강제; (사전 위조) 시작 전부터 `passes:true` 로 위조된 기능도 믿지 않고 재검증 대상으로 잡아 false 강제·exit 1.
>
> **광범위 검증(2026-07-03) 완료** — 실모델 3종:
> 1. **다기능 연쇄**: 3기능(add·sub·greet)을 무인 완주 — 구현→독립검증→커밋 ×3, exit 0. 도중 검증 FAIL→재시도 회복이 자연 발생해 재시도 경로도 실전 실증.
> 2. **실제 회귀 파손 감지**: 기존 `add(2,3)==5` 계약을 깨는 변경(add→곱셈)을 evaluator 는 목표충족 PASS 했으나 **회귀 게이트가 실제 파손을 잡아 보류** — 이중 게이트(evaluator PASS ≠ 통과) 실증.
> 3. **막힘→보류→계속 진행**: 수학적 불가능 기능(2 초과 짝수 소수)이 재시도 소진 후 보류(escalate)되고 루프는 다음 기능으로 계속 진행, exit 1. 보류 후 기능의 PASS 완주 경로는 ①로 실증. 이 판들이 겹친 API 불안정 구간(Connection closed·빈 출력)에서도 **오염 0**(가짜 통과·가짜 커밋 없음) — 판정 불가 시 보수적 FAIL 이 설계대로 동작.
>
> **광범위 검증 중 드라이버 강화**: `CLAUDE_BIN` 고정(무인 환경 PATH 비결정성 회피 — 실제 겪음), stderr·FAIL 사유 로깅(관측성 — 빈 출력의 원인 진단 가능), evaluator 빈 출력 1회 재시도(인프라 오류가 구현 재시도를 낭비하지 않게). 부수 교훈: "불가능해 보이는" 사양(`f()==1 과 f()==2 동시 참`)을 모델이 `__eq__` 오버로드로 **합법 충족** — 허점 있는 사양은 게임되므로, 기능 사양은 타입·실행 조건까지 검증 가능하게 써야 한다.
>
> **e2e·한계 테스트에서 배운 것**:
> 1. evaluator 가 테스트를 *직접 실행*하려면 `bypassPermissions` 필요(acceptEdits 는 Bash 를 헤드리스에서 차단) → 무인 자율은 격리 환경 전제라 정당.
> 2. `parse_verdict` 는 최종 판정 라인 기준이어야 함(본문 'FAIL' 단어 오탐 방지).
> 3. **위조 방어 결함 발견·수정(한계 테스트가 잡음)**: 구현 세션 모델은 규율을 어기고 디스크 `feature_list.passes` 를 스스로 true 로 조작한다. 초기 드라이버는 디스크 `passes` 를 신뢰해 **모델 위조가 드라이버 보류를 이겼다**(회귀 실패인데 완료로 종료). 수정: 드라이버가 검증한 것(`verified` 집합)만 통과로 치고, FAIL 시 `passes` 를 false 로 강제 → 실모델에서 방어 확인. **교훈: 규율1("드라이버 단독 기록")은 디스크 상태를 신뢰하지 않고 드라이버가 판정을 *소유*할 때만 성립한다.**
> 4. 남은 한계(정직): 모델이 남긴 `verify_gate` 위조 *기록*은 디스크에 남을 수 있다. autoloop 은 그 기록에 의존하지 않아(evaluator 출력을 직접 파싱) 루프 무결성엔 영향 없으나, 대화형 Stop 게이트에는 여전히 위조 우회 여지가 있다(플러그인 레벨 기존 한계).

## 1. 이미 깔린 기초 (플러그인 = 세션 안)

자동 루프가 의존하는 강제·검증 인프라는 추가 작업 없이 존재한다.

| 필요 | 제공 | 분류 |
|---|---|---|
| 작업 선택(one-feature-per-session) | `scripts/next_feature.py` + `feature_list.json` | ✅ |
| 완료 게이트(검증기록 없으면 종료 차단) | `scripts/verify_gate.py` (Stop) | 🔒 강제 |
| 조기종료 차단(미통과 남으면 계속) | `scripts/stop_guard.py` (Stop) | 🔒 강제 |
| 신선 컨텍스트 독립 검증 | `agents/evaluator.md` (`isolation: worktree`) | 🧩 서브에이전트 |
| 위험행위 차단 | `scripts/policy.py` + `templates/.claude/settings.json` | 🔒 강제 |
| 감사 추적 | `scripts/audit.py` → `.omniharness/audit.jsonl` | 🔒 강제 |
| 인계 아티팩트 | `claude-progress.txt`·`feature_list.json` | ✅ |

→ 갭분석 §2-3에서 "비어 있다"던 P0/P1 항목(강제 계층·hooks·신선검증·인계)이 **현재 레포에 모두 구현됨.** 과거 비판받던 자기평가(resume 채점)도 evaluator의 worktree 격리로 해소.

### 위조 경로 — 실재 확인 (`policy.py` 점검)

`verify_gate`는 PASS 기록의 *존재*만 강제하고, `policy.py`는 다음을 **막지 않는다**:
- `python verify_gate.py --record "<feat>" PASS` (Bash 호출) — deny/ask 패턴에 안 걸림
- `.omniharness/verify/<id>.json` 직접 `Write` — `SECRET_PATH`에 안 걸림

→ 모델이 evaluator를 건너뛰고 **가짜 PASS를 위조하는 경로가 둘 다 열려 있다.** 자동 루프에서 #4(모델 밖 독립 검증 + 드라이버 단독 기록)를 지키지 않으면 루프는 자기평가 연극으로 퇴화한다.

## 2. 자동 루프 차단점 — 전부 "세션 밖" 문제

in-session 훅으로는 원리적으로 불가능하고, 외부 드라이버가 채워야 하는 것들.

| # | 차단점 | 왜 막히나 | 드라이버 해결책 |
|---|---|---|---|
| 1 | 세션 반복 | Stop의 `block`은 *같은 세션 안* 신호. `claude -p` 단발은 끝나면 끝 | `claude -p`(또는 `claude-agent-sdk`)를 루프로 재호출 |
| 2 | 세션 간 인계 | `resume`(단일세션)은 컨텍스트 소진 — 갭분석 §2-4 핵심 결함 | **컨텍스트 리셋 + 재주입**: 매 세션 새로 띄우고 인계 떠먹임 |
| 3 | 인계 주입 신뢰성 | 실측: `-p`에서 SessionStart `additionalContext` 모델 도달 ~50%(6연타 0/6). [[sessionstart-p-mode-unreliable]] | 인계를 **첫 프롬프트 본문에 직접 주입**(SessionStart 훅 의존 금지) |
| 4 | 검증 위조 | `verify_gate`는 PASS 기록의 *존재*만 강제 → 모델이 evaluator 안 부르고 가짜 PASS 기록 가능 | 검증을 **모델 밖에서 독립 실행** 후 그 결과로만 `--record`. 모델에게 기록 권한 안 줌 |
| 5 | 막힘/무한루프 | 같은 기능 반복 FAIL·진척 0 감지 못 함 | 재시도 한도·진척 측정·에스컬레이션·중단 |
| 6 | 자동 커밋/승급 | `git push`는 ask, `promote`는 사람 승인 | 자동 커밋 정책 + 게이트 통과 시 자동 promote |
| 7 | 목표 분해 | 상위 목표 → `feature_list` 채우는 주체 없음 | 1회 사람 또는 드라이버의 분해 단계 |

### 추가 점검에서 드러난 차단점

| # | 차단점 | 해결책 |
|---|---|---|
| A | **Stop 게이트 vs 드라이버 종료**: 검증을 모델 밖으로 빼면(#4) 구현 세션 종료 시 PASS 기록이 없어 `verify_gate`/`stop_guard`가 Stop을 block | 아래 §2-1 — 자동 모드에선 Stop 게이트 역할을 **드라이버가 인수** |
| B | **회귀 미감지**: evaluator는 현재 기능만 봄 → A 통과 후 B 작업이 A를 깨도 못 잡음 | 드라이버가 매 기능 후 **전 기능 재검증/통합 테스트** |
| C | **feature_list 동시쓰기**: 모델도(라이브 ② WARN) 드라이버도 `passes`를 씀 | `passes` 기록 주체를 **드라이버로 단일화**, 모델은 수정 금지 |
| E | **fid 안정성**: `verify_gate` fid=`sha256(desc)` → desc 미세 변경 시 기록 무효 | 드라이버가 **canonical desc**를 구현·검증·기록에 동일하게 전달 |

### 2-1. (A)의 해법 — 자동 모드에선 게이트를 드라이버가 인수

플러그인의 Stop 게이트(`stop_guard`·`verify_gate`)는 **대화형/반자동** 세션용이다. 완전 자동 루프에선 그 역할(완료 판정·미통과 차단)을 드라이버가 가져간다:

- 구현 세션은 `feature_list` 없이(또는 해당 기능 미등록) **단일 작업만** 지시 → Stop 게이트가 안 막아 세션이 깔끔히 종료, 드라이버가 제어 회복.
- 검증·`--record`·`passes` 갱신·커밋·종료조건을 **전부 드라이버**가 오케스트레이션.
- 안전장치: 게이트가 막히는 경우라도 Claude Code는 **8연속 block에서 강제 종료**(`CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`로 조정)하고, `--max-turns N`로도 캡 → 드라이버는 반드시 제어를 되찾는다.

### 검증된 CLI 사실 (claude-code-guide, 2026-06-30)

| 사실 | 자동 루프 함의 |
|---|---|
| `-p` 프롬프트 **본문은 100% 결정적**으로 모델에 도달(SessionStart `additionalContext`는 ~50%·10KB 캡) | 인계를 **본문 주입**(#3) — SessionStart 의존 금지 |
| `claude --agent evaluator -p "..."` → **fresh 독립 세션**(worktree 격리·도구 제한 유지) | 모델 밖 독립 검증(#4) 실현 수단 |
| Stop block은 **8연속 시 강제 종료**, `--max-turns` 캡 존재 | 드라이버 제어 회복 보장(A·#5) |
| ⚠️ block-cap 종료 시 **exit code 계약은 문서 미확정**(guide도 flag) | 드라이버가 **타임아웃**으로 자체 방어 필요 |

## 3. 최소 드라이버 의사코드 (얇게 — 네이티브 재구현 금지)

[[harness-definition]] 원칙: Claude Code가 네이티브로 하는 것(에이전트 루프·도구·스킬·hooks·서브에이전트)은 그대로 두고, 드라이버는 세션 밖 오케스트레이션만.

```
while 미통과_기능 존재 and 예산/재시도 한도 내:
    feat = next_feature.py()                              # 플러그인 스크립트 재사용(canonical desc, #E)
    ctx  = read(progress, feature_list, wiki/index)       # 인계를 직접 읽어
    # 구현 세션: feature_list 미등록·단일작업 → Stop 게이트 비활성(#A). 타임아웃·max-turns 방어.
    timeout T  claude --max-turns N -p  "<ctx 본문주입> + 'feat 를 구현하라'"   # 본문 주입(#3)
    # 검증: 별 세션·격리 evaluator → 모델 밖 독립(#4). 위조 경로 차단.
    verdict = timeout T  claude --agent evaluator -p  "feat 가 충족됐는지 작업트리만 보고 PASS/FAIL"
    # 회귀(#B): 직전까지 통과한 전 기능도 재검증/통합테스트
    regress = run_full_suite()
    if verdict == PASS and regress == OK:
        verify_gate.py --record feat PASS                 # 드라이버만 기록(#C: passes 단일 기록자)
        feature_list[feat].passes = true ; git commit     # push는 settings 조정/드라이버(#6)
        update claude-progress.txt                        # 다음 세션 인계(#2)
    else:
        retries[feat]++ ; if over_limit: escalate/skip(#5)
```

드라이버가 채우는 건 §2의 #1~#7·A~E 전부 = "세션 밖에만 있는 것". 약 150~250줄. Claude Code 네이티브(에이전트 루프·도구·스킬·hooks·서브에이전트)는 손대지 않는다.

## 4. 리스크 (안 풀면 "연극"이 됨)

1. **위조 우회가 최대 위험** — 검증을 모델 밖으로 빼지 않으면(#4) 자동 루프는 모델이 스스로 PASS 도장 찍는 자기평가로 퇴화. evaluator를 별 세션으로 돌리거나 결정론 테스트를 직접 실행해야 루프가 *닫힌다*.
2. **무인 운영 = 환경 격리 필수** — 갭분석 §6.2 경고: 야간 무인으로 `bypassPermissions`를 쓰려면 컨테이너/worktree 같은 **실제 격리**가 전제. 격리 없는 bypass는 위험.
3. **인계 품질이 생명** — 긴 작업은 컨텍스트 리셋으로 풀되, 매 세션 주입 인계(progress·다음기능·위키)가 부실하면 one-shotting 실패가 재현. #3을 프롬프트 직접 주입으로 견고히.
4. **종료 감지를 타임아웃으로 이중화** — block-cap 종료 시 exit code 계약이 문서로 확정되지 않았으므로(guide flag), 드라이버는 exit code에만 의존하지 말고 `timeout` + `--max-turns`로 제어 회복을 보장한다.
5. **모델에게 기록 권한을 주지 말 것** — 구현 세션이 `verify_gate --record`/`.omniharness/verify/*` 를 쓰면 위조가 성립한다(§1 확인). 자동 모드에선 그 기록을 **드라이버만** 수행하고, 모델 세션이 쓴 기록은 신뢰하지 않는다.

## 5. 구현 방식 트레이드오프

| | bash 드라이버 | claude-agent-sdk (Python) |
|---|---|---|
| 분량 | ~150줄, 의존성 0 | 더 무겁지만 구조화·관측성·예산제어 견고 |
| 재사용 | `tests/live.sh` 패턴 그대로 — `claude -p` 반복 | 메모리의 원래 omni-harness 설계([[superharness-vs-omniharness]]) |
| 적합 | 빠른 동작 확인·소규모 루프 | 장기 무인 운영·정교한 막힘 처리 |
| 검증(#4) | `claude --agent evaluator -p` (fresh 격리 세션) | SDK로 fresh 세션 spawn |
| 종료 방어 | `timeout` + `--max-turns` | SDK 타임아웃·turn 한도 |

## 7. 최종 점검 판정

**구조적 showstopper 없음.** §2의 차단점 #1~#7과 추가 점검 A~E가 전부 해결 가능하며, 해결 수단(`-p` 본문 결정성·`--agent evaluator`·8-block cap/`--max-turns`)은 claude-code-guide로 검증됐다. 단, 루프가 "연극"이 아니라 실제로 닫히려면 다음 **5개 규율**이 전제다:

1. 검증·기록은 **드라이버 단독**(모델 세션에 기록 권한 금지) — 안 지키면 위조로 무력화(§1).
2. 인계는 **`-p` 본문 주입**(SessionStart 의존 금지) — #3.
3. 검증은 **`--agent evaluator` fresh 세션** — 자기평가 금지(#4).
4. **회귀 패스**를 매 기능 후 — evaluator 단일기능 한계 보완(#B).
5. **타임아웃 + `--max-turns`**로 종료 이중 방어 — exit code 미확정 대비(리스크 4).

→ 이 5개를 지키면 완전 자동 루프는 현재 플러그인 위에서 **얇은 외부 드라이버 하나로 성립**한다. 미확정 1건(block-cap 종료 exit code 계약)은 타임아웃으로 흡수되므로 showstopper가 아니다.
